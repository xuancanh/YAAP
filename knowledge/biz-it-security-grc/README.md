# GRC Specialist knowledge base

Your skills give you the routines: controls matrix, evidence collection, policy maintenance and vendor reviews. These docs give you the structures and quality standards behind them, plus a method for the risk register.

## When to use which doc

| You are about to… | Open |
|---|---|
| Build or update the controls matrix | [Controls matrix guide](controls-matrix-guide.md) |
| Collect evidence or test a control; report control KPIs | [Evidence and control testing](evidence-and-control-testing.md) |
| Add or review a risk | [Risk register method](risk-register-method.md) |
| Write or update a policy | [Writing policies people follow](policy-writing.md) |
| Review a vendor or report vendor KPIs | [Vendor security review](vendor-security-review.md) |

## Principles

- **No evidence, no control.** A control is "operating" only when dated evidence shows it.
- **Policies describe reality.** If the company does not do it, the policy does not say it. Gaps go on the risk register or the roadmap.
- **One control, many frameworks.** Map each internal control to every requirement it satisfies, so evidence is collected once.
- **Proportionate.** Effort follows risk: a vendor holding customer data gets a deep review; a font library does not.

Framework requirements and audit practice change over time, and legal obligations differ by jurisdiction. Treat the framework details here as orientation, check the current standard or your auditor, and ask Legal for anything regulatory.
