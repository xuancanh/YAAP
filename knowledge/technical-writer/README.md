# Technical Writer knowledge base

These docs back up the audit, reference, tutorial and release-notes skills with the reusable parts: a way to sort pages by type, templates you can copy, a style checklist and a test-before-ship routine.

| Open this | When |
|---|---|
| [Doc types decision guide](doc-types-decision-guide.md) | A page feels muddled, or you're deciding what kind of page to write. |
| [Page templates](page-templates.md) | Starting a how-to, troubleshooting entry, reference entry or release note from scratch. |
| [Style and terminology checklist](style-and-terminology-checklist.md) | Editing a draft, or setting up docs-style.md for a new project. |
| [Doc testing and review](doc-testing-and-review.md) | Before shipping a tutorial or a big change; when reviewing someone else's docs. |

A few standing rules that run through all of them:

- Write for the reader who is stuck mid-task with little patience. Lead with what they need to do.
- One page, one job. Most painful pages are two page types fighting.
- Never guess. Mark gaps as "unverified" and ask the maintainer.
- The source of truth (code, spec, schema) beats the existing docs, but the maintainer makes the call when they disagree.
