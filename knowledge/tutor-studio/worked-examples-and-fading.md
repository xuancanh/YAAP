# Worked examples and fading

When students are new to a type of problem, studying a fully worked solution usually teaches more than struggling alone, because their working memory is free to notice the structure. As they improve, you remove the support step by step until they work on their own. Rosenshine's widely used "Principles of Instruction" summarise this: give models and worked examples, guide practice, check understanding, and give scaffolds for difficult tasks, then remove them.

## Designing a good worked example

1. **Pick a clean first example.** Use small numbers, no distracting context, and the method visible in every line.
2. **Write the steps as the student should write them.** Same layout, same notation.
3. **Say the why next to the what.** "Subtract 5 from both sides *to get the x-term alone*."
4. **Pair it.** Follow each worked example straight away with a near-identical problem for the student: same structure, new numbers.
5. **Then vary one thing at a time.** Negative numbers, then a fraction, then a word problem.
6. **Include one non-example** once the method is secure. "Here's a wrong solution. Where did it go wrong?"

## The fading sequence

| Stage | You | Student |
|---|---|---|
| 1. Full example | Solve it, thinking aloud | Watches, then explains a step back to you |
| 2. Partially worked | Do the first steps | Finishes it |
| 3. Faded | Give only the first step or a prompt | Does the rest |
| 4. Independent | Watch silently | Solves it alone, explaining their reasoning |
| 5. Proof it stuck | A new problem later in the session | Solves it unaided |

Move to the next stage when they succeed reliably, roughly two in a row without help. Step back a stage if they stall. Stage 5 is the evidence for the session log.

## Self-explanation prompts

Ask these while the student studies an example or works through a problem:

- "Why is this step allowed?"
- "What would change if this number were negative?"
- "Which step would you do first next time, and how would you know?"
- "How is this one like the last one, and how is it different?"

## Choosing the example's style for the student

The student file records what lands. Some students need a visual model first (a bar model, a number line, a diagram). Others need the algebra straight away. Some need the student's own interests in the context ("football fractions"). Use their style for the first example, then make sure they also see the standard exam format.

## Worked example: two-step equations

- **Full:** 3x + 5 = 20. "Subtract 5 from both sides to remove the constant: 3x = 15. Divide both sides by 3: x = 5. Check: 3 × 5 + 5 = 20 ✔."
- **Paired:** 4x + 3 = 19 (student).
- **Partially worked:** 2x − 7 = 9. "Add 7 to both sides: 2x = __", and the student finishes.
- **Faded:** 5x + 12 = 2, with the prompt "What's stuck to the x-term?"
- **Independent:** −3x + 4 = 19.
- **Proof it stuck** (end of the session): 6 − 2x = 14.

## Common mistakes

- Using a hard first example "to make it realistic". Complexity hides the method.
- Explaining for ten minutes, then giving ten problems. Alternate: example, problem, example, problem.
- Removing support too fast, or never removing it. Watch the success rate.
- Showing many examples that all look the same, so the student copies the surface instead of learning the structure.
- Never asking the student to explain. Correct answers can hide a broken model (see [Diagnosing misconceptions](diagnosing-misconceptions.md)).
