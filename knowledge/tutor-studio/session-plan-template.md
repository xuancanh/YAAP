# Session plan template

A good session has one objective, starts with retrieval, models before practice, and ends with proof the objective was met. The template below fits 45–60 minutes. Scale the middle sections for shorter or longer sessions.

## Template

```markdown
# Session — <student> — <date> (<length>)
From the file: last "struggled" → <...>; retrieval targets → <...>

Objective (capability): <student can ... unaided>
Success check: <the specific problem/task that proves it>

| Min | Phase | Plan | Notes |
|---|---|---|---|
| 0–5 | Retrieval opener | 3 questions: last session / 2 ago / older | |
| 5–10 | Homework check | Mark together; one error explained | |
| 10–20 | Model | Worked example(s) in their style | |
| 20–40 | Guided → independent | Faded practice, 2 in a row then step up | |
| 40–50 | Proof it stuck | Success-check problem, unaided | |
| 50–55 | Wrap-up | Student says what they learned in one line | |
| 55–60 | Homework set | Short; today's objective plus 2 older items | |

Plan B (low-energy day): <different mode: whiteboard game, teach-it-back, past-paper sprint>
Interest hook: <one example using their interests>
```

## Writing a good objective

- **Write it as a capability**: "solve two-step linear equations with negative coefficients", not "algebra".
- **Pitch it at the edge of the diagnosis.** It should be just beyond what they can do now.
- **Make it testable in one problem**, so the success check is obvious.
- **Keep it to one per session.** A second objective only appears if the first is clearly secure.

## The three-line log (after every session)

```
<date> — Covered: <objective>.
Stuck: <evidence, e.g. "solved 6 − 2x = 14 unaided, explained each step">.
Struggled: <specific; plan: "negative divisor sign errors → opener + 2 homework items">.
```

The "struggled" line becomes the starting point for next session's plan. The "stuck" lines are what parent updates are built from.

## Worked example: 60 minutes, Year 10 maths

**From the file:** last session she struggled with expanding brackets that have a negative outside. Retrieval targets: simplifying fractions (two sessions ago) and area of a triangle (a month ago).

**Objective:** factorise quadratics of the form x² + bx + c, including negative c.
**Success check:** factorise x² − 2x − 15 unaided.

| Min | Plan |
|---|---|
| 0–5 | Opener: −2(x − 4); simplify 14/21; area of a triangle with base 6 and height 5 |
| 5–10 | Homework: 5 of 6 correct; one sign error in −3(2 − x), talked through |
| 10–20 | Worked example x² + 5x + 6 using "find two numbers that multiply to 6 and add to 5", checked by expanding. Then x² + x − 6, pointing out the signs |
| 20–40 | Partially worked → faded → independent: x² + 7x + 12, x² − x − 12, x² − 8x + 15, x² + 2x − 24 |
| 40–50 | Success check x² − 2x − 15 → (x − 5)(x + 3) ✔, checked by expanding |
| 50–55 | "Find a pair that multiplies to c and adds to b, then check the signs by expanding" |
| 55–60 | Homework: 6 quadratics (two with negative c), plus 2 expansion items with a negative outside the bracket |

**Plan B:** factor-pair speed game on the whiteboard.

**Log:** "Covered factorising x² + bx + c. Stuck: (x − 5)(x + 3) unaided with check. Struggled: picked the wrong sign pair twice when c was negative → opener next time."

## Exam-season variant

Swap the model and guided phases for a timed past-paper section (15–20 minutes). Then mark it against the official mark scheme, and choose topics from the student's error log. Keep the retrieval opener.

## Common mistakes

- No success check, so "it went well" is the only evidence.
- Too many objectives. Nothing gets secured.
- Skipping the homework check, so homework stops getting done.
- Planning without opening the student file first.
