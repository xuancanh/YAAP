# Backward design worksheet

Backward design starts from what learners will be able to do, then decides how you'll know they can, and only then plans lessons. It's the core idea in Wiggins and McTighe's *Understanding by Design*, and it keeps courses short and useful.

## 1. The learner

```
Who it's for: ___
They can already: ___ (assumed knowledge, stated on the sales page)
It's not for: ___ (say this plainly; the wrong buyer becomes a refund)
Their real goal: ___
```

## 2. Outcomes (3-5)

Write each as something observable the learner can do at the end. Use verbs you could watch someone do: build, write, diagnose, plan, choose, present. Avoid "understand", "know" or "be familiar with".

| # | By the end, learners can… | Evidence they can (the exercise or project) |
|---|---|---|
| 1 | Write a one-page project brief a client signs off | Final brief, reviewed against a checklist |
| 2 | | |

If you can't name the evidence, the outcome is too vague.

## 3. Module ladder

One module per outcome (or per step toward one). For each:

```
Module N: [outcome it serves]
Needs from earlier modules: ___
Quick win in this module: ___
Exercise: ___
```

**Dependency check:** read the "needs" column top to bottom. If module 4 needs something taught in module 6, reorder.

**Quick win in module 1:** a small, real result in the first hour. Early progress keeps people going.

## 4. Lesson template

```
Lesson: [title as a result, e.g. "Price your first package"]
One idea: ___
Length: 5-12 min (split if longer)
Show: [example or demo]
Do: [the exercise — this is where learning happens]
Check: [how they know they got it]
Resource: [sheet, template, checklist]
```

Every lesson ends with something to do. Watching alone rarely builds skill.

## 5. Padding check

Go through each lesson and ask:

- Does it serve an outcome on the list? If not, cut it or make it a bonus.
- Could it be a one-page resource instead of a video?
- Is the intro longer than a minute?
- Is the same idea taught twice?

Be honest about length. A tight 4-hour course that gets finished beats a 12-hour course that doesn't.

## 6. Revision from evidence

After each cohort or a few months of sales, look at:

- Where learners stop (lesson completion data).
- Which lessons draw the most questions.
- Which exercises are skipped or done wrong.
- Refund reasons.

Fix the lessons behind the clusters first. Keep a changelog: date, what changed, why.

## Worked example

Draft outcome: "Understand social media marketing." Not observable.

Revised: "Plan a four-week content calendar for one platform, with three post formats and a way to measure results." Evidence: the learner's calendar, checked against a rubric. Modules follow: pick platform and audience, choose formats, write the first posts, set up measurement, review week one.

## Common mistakes

- Starting with a list of topics you know a lot about.
- Outcomes that are really topics.
- Theory modules before any doing.
- No assumed-knowledge line, so beginners and experts both feel lost.
