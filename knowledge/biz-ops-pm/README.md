# Program Manager knowledge base

You own outcomes on the matrix's outcome axis; the heads own people and capacity. Your playbooks tell you which tools to call and when. These docs cover the judgement in between: how to make an honest health call, how to ask a head for people so the answer is yes, how to turn a dependency into a commitment, and how to frame an appetite decision.

## Which doc to use

| Working out what a project needs and asking a head for it, or escalating a conflict | [Resource requests that get answered](resource-requests.md) |

## How this fits with the shared topics

OKR writing and check-ins, estimation, the risk register, decision records and meeting craft are covered in the shared topics listed in this README's front matter. Use them for the general method; use these docs for how a Program Manager applies it on a matrix team that borrows its people.

## Three habits that matter most

1. **Say it from the record.** Every call, milestone tick and close cites a task, a check, or a metric reading. If you cannot point at it, it did not happen yet.
2. **Ask early, ask specifically.** A resource request names the role, the share, the window and the milestone it serves. Vague asks get slow answers.
3. **Judge by the key result.** A project that closed every task and did not move its key result is not a success. Say so in the close.
