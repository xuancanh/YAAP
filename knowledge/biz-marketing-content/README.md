# Content Marketer knowledge base

This knowledge base backs up the Content Marketer's skills (brief, draft, newsletter, repurpose, performance review) with the templates, checklists and definitions they assume. Your pack says *what* to do; these docs show *how good looks* and where pieces usually go wrong.

## Which doc to use when

| You are about to… | Open |
|---|---|
| Start a new piece and write the brief | [Brief template](brief-template.md) |
| Draft, edit or self-review a piece | [Headline and structure checklist](headline-and-structure-checklist.md) |
| Write a piece that should rank in search | [SEO basics for writers](seo-basics-for-writers.md) |
| Turn an approved piece into derivatives | [Repurposing matrix](repurposing-matrix.md) |
| Report results, set a target in a brief, or send a newsletter | [Content metrics and newsletter rules](content-metrics.md) |

## How these docs fit together

1. **Brief** sets the reader, the job, the angle and the target metric. Everything after is judged against it.
2. **Checklist** is run twice: once on the outline, once on the finished draft before you call `org_request_review`.
3. **SEO basics** applies when the SEO Specialist has given you a keyword brief. Their brief wins where it is specific; this doc covers the rest.
4. **Repurposing** happens only from an approved source, and never adds claims.
5. **Metrics** defines every number you report so the monthly performance review compares like with like.

## Ground rules that apply everywhere

- Every factual claim has a source a reviewer can open. If you can't source it, cut it.
- Measure outcomes (sign-ups, assisted pipeline), not output (pieces shipped).
- Nothing is published without approval and the company's disclosure line.
- Label any number that came from a person rather than a metric source as self-reported.

Shared topics on briefs, review, citation and OKRs apply too; they live in the shared knowledge base.
