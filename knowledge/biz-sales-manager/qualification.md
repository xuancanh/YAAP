# Qualification frameworks

Qualification answers two questions: **can this deal close**, and **should we spend time on it**. A framework is only useful if every element is backed by evidence. The rule used throughout this doc: mark each element **known** (you have the evidence: a quote, an email, a meeting note, a document), **assumed** (it's believable but unconfirmed) or **unknown**. An assumed element is a question to ask on the next call, not a fact.

## BANT: a quick screen

BANT is usually credited to IBM. It's a fast check that a lead is worth a real discovery conversation.

| Letter | Question | Evidence that makes it known |
|---|---|---|
| Budget | Can they pay for this, from a budget that exists or can be created? | Stated budget range, or a named source of funds |
| Authority | Who decides and signs? | Named decision-maker and how they decide |
| Need | What problem would this solve, and how badly? | Their words describing the problem and its cost |
| Timeline | When do they need it, and why then? | A date tied to an event (a renewal, a launch, a deadline) |

Use BANT for SDR handoffs and inbound triage. Its weakness is that buyers often don't have budget or a timeline *until* the need is clear, so asking for budget first can disqualify good deals. Start with need.

## MEDDICC: the default for real deals

MEDDIC was created at PTC in 1996. MEDDICC adds a second C for Competition, and MEDDPICC adds P for Paper process. Your deal-review playbook uses the MEDDICC elements plus paper process.

| Element | What it means | Discovery questions | Known when |
|---|---|---|---|
| **Metrics** | The measurable outcome the customer expects | "How will you measure success? What does it cost you today?" | A number in the buyer's own terms |
| **Economic buyer** | The person who can release the money and say yes when others say no | "Who signs off on spend like this? Have they seen the case?" | You've met or heard directly from them |
| **Decision criteria** | What they'll judge options on (technical, commercial, risk) | "What does a good solution have to do? What would rule one out?" | Written or confirmed criteria |
| **Decision process** | The steps and people from now to a decision | "Walk me through how you decided on the last tool like this." | Dated steps and named people |
| **Paper process** | Legal, security, procurement, and the signature path | "What does security review need? Who redlines contracts? How long did it take last time?" | Steps and owners on both sides |
| **Identify pain** | The problem driving urgency and its consequence | "What happens if you do nothing this quarter?" | A consequence the buyer stated |
| **Champion** | An insider with influence who is selling for you when you're not there | "What's in it for you if this succeeds?" Then test it: will they get you to the economic buyer? | They've *acted*: shared internal information or arranged access |
| **Competition** | Alternatives, including doing nothing or building it themselves | "What else are you looking at? What happens if you don't buy anything?" | Named alternatives and where you stand |

A **champion** is the element most often over-claimed. A friendly contact who takes your calls isn't a champion until they've done something that costs them effort.

```markdown
| Decision criteria | | | |

| Paper process | | | |
| Identify pain | | | |
| Champion | | | |
| Competition | | | |
Verdict: advance / re-qualify / disqualify, because <reason>
```

How strict to be at each stage (which elements must be known before Proposal or Commit) is a team setting. Write it next to the stage exit criteria in kpis.md.

## Common pitfalls

- Filling in every box with "assumed" and calling the deal qualified.
- Treating the person who replies quickest as the champion.
- Leaving "no decision" out of Competition. Doing nothing is often the strongest competitor.
- Starting paper process only after a verbal yes. Security and legal steps belong in the close plan from discovery onwards.
- Never disqualifying anything. A disqualified deal recorded as a decision keeps the pipeline honest and frees time.
