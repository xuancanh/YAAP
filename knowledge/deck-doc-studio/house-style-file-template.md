# House style file template

A style file is only useful if someone can hold it in their head. Keep it to about a page of short, imperative rules.

## Building it

1. Collect three to five deliverables the user likes (their own or ones they admire).
2. Note what they have in common: tone, sentence length, heading style, number and date formats, colours and fonts.
3. Draft the rules below from those observations.
4. Confirm with the user: "I noticed you always… Keep that as a rule?"

Building from real examples is faster and more accurate than asking someone to describe their style from scratch.

## Template

```
# House style — [name] · updated [date]

## Voice
- [Formality: e.g. "Plain and direct. Contractions are fine."]
- [Person: e.g. "We for the organization, you for the reader."]
- [Sentence length: e.g. "Mostly short. Split anything over 25 words."]
- [Words to avoid: e.g. "Never 'utilize', 'leverage', 'synergy'."]

## Headings and lists
- [Case: e.g. "Sentence case for all headings."]
- [Headings state points, not topics.]
- [Bullets: e.g. "No full stops on fragments; full stops on sentences."]

## Numbers and dates
- [e.g. "Numbers under ten in words, 10 and above in figures."]
- [e.g. "Dates: 4 November 2026. In tables: 2026-11-04."]
- [Currency and units: e.g. "£1.2m, 15%, 3 km."]

## Names and terms
- [Product and team names spelled exactly: ___]
- [Preferred terms: e.g. "customers, not users".]

## Visuals
- [Palette: primary ___, accent ___, neutrals ___ (hex)]
- [Fonts: headings ___, body ___; minimum size on slides ___]
- [Charts: one highlight colour; label directly; source line bottom-left.]
- [Logo use: ___]

## Documents
- [Front matter: status, date, owner on every document.]
- [Page size and margins: ___]
```

## Applying it

Every deliverable goes through the style file before delivery. The most common slips to check: heading case, date formats, number style, product names, and colours drifting from the palette.

## Auditing a document

Return either a marked list or a corrected version, as asked. A marked list looks like:

```
p.2, heading "Our Q3 Results" → sentence case: "Our Q3 results" (Headings rule)
p.3, "utilize" → "use" (Words to avoid)
p.5, "11/04/26" → "4 November 2026" (Dates)
Chart 2 uses four bright colours → one highlight, rest muted (Charts)
```

Cite the rule for each change so the user can disagree with the rule, not just the edit.

## Evolving it

- If the user overrides the same rule twice, propose changing the rule.
- Date each update and note what changed.
- Remove rules nobody follows. A style guide that loses arguments with reality loses its authority.

## Worked example

From three reports the user likes: all use sentence-case headings, short paragraphs, metric units, a navy-and-teal palette, and dates written out in full. They never use exclamation marks. Draft rules: five lines under Voice, three under Headings, two under Numbers, the palette in hex. User confirms and adds: "Always spell out acronyms on first use." The file is under a page.

## Common mistakes

- Style guides copied from a large organization, dozens of pages long.
- Vague rules ("be professional") that can't be checked.
- No palette hex values, so colours drift.
- Never updating it.
