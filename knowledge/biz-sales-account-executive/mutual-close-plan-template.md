# Mutual close plan template

A mutual close plan lists every step, on both sides, from today to the buyer's go-live, with owners and dates. It is shared with the buyer and agreed by them. If it only lives in your head or only lists your tasks, it is a wish list.

## Why it works

- It exposes unknown steps (security review, legal, board approval) while there is still time.
- It anchors the close date to the buyer's own deadline, not ours.
- It gives your champion a document to sell internally.

## Template

```
Deal: <account> — <solution>
Buyer's goal: <outcome and metric, in their words>
Event driving the date: <why this date matters to them, e.g. contract with current vendor ends, new team starts>
Target go-live: <date>   Signature needed by: <date>

| # | Step                          | Owner (side, name) | Due     | Status   |
|---|-------------------------------|--------------------|---------|----------|
| 1 | Discovery recap agreed        | Us — AE            |         |          |
| 2 | Technical evaluation / POC    | Both — SE + buyer  |         |          |
| 3 | Success criteria signed off   | Buyer — champion   |         |          |
| 4 | Security review               | Buyer — IT         |         |          |
| 5 | Proposal presented            | Us — AE            |         |          |
| 6 | Economic buyer review         | Buyer — sponsor    |         |          |
| 7 | Legal / redlines              | Both               |         |          |
| 8 | Procurement / vendor setup    | Buyer — procurement|         |          |
| 9 | Signature                     | Buyer — signer     |         |          |
|10 | Kickoff                       | Us — onboarding    |         |          |

Risks: <risk, owner, mitigation>
Last updated: <date>, agreed with <buyer name>
```

## Build it backwards

1. Start from the buyer's driving event and go-live date.
2. Subtract onboarding time to get the signature date.
3. Ask the buyer how long each of their steps takes (legal, security, procurement). Use their answers, not your hopes.
4. Place the remaining evaluation steps before that.
5. If the dates do not fit, say so now and agree what changes: scope, sequence or go-live.

## Worked example (shortened)

> **Goal**: finance team closes the month in five days instead of ten, starting with the March close.
> **Driving event**: new CFO's target for the quarter.
> **Go-live**: 1 March → **signature by** 1 February (onboarding usually needs about four weeks for this scope — confirm with onboarding).
> Security review: buyer's IT says three weeks → starts by 5 January.
> Legal: their counsel needs two weeks → redlines start 15 January.
> Proposal to CFO: 10 January.

Every date came from a person; the plan shows that signature by 1 February is only possible if security starts on time. That becomes the first risk.

## Keeping it current

- Review it with the champion weekly in late stages.
- Update status and dates as they change, with the reason.
- If a buyer-side step slips twice, the close date in the CRM moves too.
- Close-plan coverage (see [sales metrics](sales-metrics.md)) counts only plans updated within the agreed window and confirmed by the buyer.

## Pitfalls

- **Seller-only steps.** If every owner is on our side, the buyer hasn't agreed to anything.
- **No driving event.** Without a reason for the date, it will slip.
- **Hidden steps found late.** Always ask: "What has to happen on your side that we haven't listed?"
- **Plan as pressure.** It is a planning tool, not an ultimatum; if the buyer pushes back on dates, believe them.
