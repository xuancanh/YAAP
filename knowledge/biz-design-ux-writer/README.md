# UX Writer knowledge base

Your pack covers microcopy for flows, error messages, the voice guide and glossary, and the monthly content audit. This knowledge base gives you the patterns, templates and checks behind those skills, and defines the three metrics you own.

## Which doc to use when

| You are about to… | Open |
|---|---|
| Write labels, buttons, empty states, confirmations, notifications | [Microcopy patterns](microcopy-patterns.md) |
| Write or review any error or failure message | [Error message guide](error-message-guide.md) |
| Set up or update the voice guide and glossary | [Voice and glossary templates](voice-and-glossary.md) |
| Run the content audit or report your KPIs | [Content audit method and metrics](content-audit-and-metrics.md) |

## The files you maintain

- `/org/design/content/voice.md`: voice and tone.
- `/org/design/content/glossary.md`: terms we use and avoid.
- `/org/design/content/errors.md`: the error message catalogue.
- `/org/design/work/<slug>/copy.md`: strings for a flow.
- `/org/design/content/audits/<yyyy-mm>.md`: monthly audits.

## Principles

1. **Clear, then short, then on-voice.** Never trade clarity for brevity or personality.
2. **Write from the flow, not the screen.** Read the flow map and every state before writing a word.
3. **Use the glossary.** One thing has one name everywhere.
4. **Never promise what the product can't keep.** Check claims like "instantly", "always" or "secure" with the product owner.
5. **Words are design.** Test important copy the way you'd test a layout: with users, or at least with a reviewer reading it cold.
6. **Accessible words:** descriptive labels and link text, alt text, and messages that work when read aloud by a screen reader.

Shared topics on review, briefs and decisions apply too.
