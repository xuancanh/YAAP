# Four hosted agents launched; our wedge is now trust

*Research date: 31 October 2026. Competitor facts come from the notes in `research_notes/Personal agent competitor gap analysis/`; our side comes from the README, `docs/roadmap.md`, `docs/agent-memory.md`, `docs/shared-accounts.md`, `docs/integrations.md`, `docs/miniapp-roadmap.md`, `docs/code-execution.md`, `docs/permissions.md`, `docs/deployment.md`, and `git log`. Where a competitor claim has no primary URL in the notes it is omitted or flagged.*

Between July and October 2026 the half of our strategic bet that said "hosted, zero-setup" stopped being a differentiator: xAI's Grok Bot (11 Aug), Meta's Muse (8 Sep), OpenAI's Dots (29 Sep) and Anthropic's Claude Duet (21 Oct) are all hosted, always-on personal agents with a per-user cloud computer, approvals, connectors and a bundled model, and Muse alone reached **10 million set-ups in about seven weeks** ([Fortune](https://fortune.com/2026/10/29/amazon-ceo-says-shopping-agents-like-metas-muse-not-great/)). The other half of the bet — safe by default, legible cost, memory you can see and veto, learning gated by a human, an agent that is your property — is where every one of those products is now being criticised: Dots and personal Grok Bots have no per-item memory UI, Muse leaked ~6,800 shared chats via enumerable share links, Grok's bots share one computer that xAI says is "not a security boundary", Duet and Dots burn an undisclosed quota on background checks, and none of the six offers a shared agent that two humans can direct with separate permissions. yaam-chat has shipped more of its own roadmap than the July document implies — provenance-tagged editable memory, human-gated skill drafts, an agent inbox with per-loop token budgets and model overrides, a paired Telegram channel, kanban delegation, Google and Microsoft connections, MCP with OAuth 2.1, and a no-network code sandbox — but it lacks the new table stakes (a cloud browser, an independent action reviewer, an email channel, push, quiet hours, a hard spend stop, a hosted plan at all) and is still single-user. The recommendation is to stop treating Phase 2 as finished, add an out-of-model action reviewer and a credential-free browser as new table stakes, pull shared multi-human agents forward from "deliberately last" to the first thing we build once the paid cloud exists, and deprioritise the public market registry, which no small product can win against 6,000-connector and 1-million-skill ecosystems.

## The bet still holds, but "hosted" is no longer the differentiator

In July, `docs/roadmap.md` framed the opportunity as "general users want the OpenClaw/Hermes experience without the OpenClaw/Hermes operations." That framing assumed the only alternatives to running a daemon were OpenClaw and Hermes. Four months later the top Hacker News comment on Muse called it "the first main openclaw-like product that has made it to the 'just works' level of usability" ([Hacker News](https://news.ycombinator.com/item?id=49615537)), and Grok Bot, Dots and Duet make the same claim with the same architecture: a named persistent agent, a per-user Linux VM with a browser, connectors with per-action scopes, approvals for send/pay/delete, and a plan quota. Every one of them is funded by a frontier lab and bundles its own model. Reviewers now recommend "Meta Muse, ChatGPT Dots, Grok Bot for ready-made agents" and Hermes or OpenClaw only for people who want to run their own ([Preuve AI](https://preuve.ai/blog/hermes-agent-review)).

The open-source pair also moved. OpenClaw became a 501(c)(3) Foundation on 8 July with a full-time team ([openclaw.ai](https://openclaw.ai/blog/introducing-openclaw-foundation)), shipped "OpenClaw 2.0" on 30 August with chat-driven onboarding and shared sessions ([openclaw.ai](https://openclaw.ai/blog/openclaw-2-accidentally)), and is now the runtime under Microsoft Autopilot ([openclaw.ai](https://openclaw.ai/blog/microsoft-autopilot-openclaw)). Hermes shipped signed Microsoft Store and notarized macOS builds, a no-API-key first-launch chat, and stable SemVer channels in v0.22.0 on 14 October ([GitHub release v0.22.0](https://github.com/NousResearch/hermes-agent/releases/tag/v0.22.0)), launched a first-party hosted tier in July ([Nous Research on X](https://x.com/NousResearch/status/2074878754485043333)) that is included in a $20/month plan ([Nous Portal](https://portal.nousresearch.com/)), and raised $90M at $1.5B on 7 October ([ReadSignal](https://www.readsignal.io/article/nous-research-hermes-90m-open-source-enterprise-agent-2026)). "Self-hosting is painful" is a weaker argument than it was.

What did not change is the pattern of complaints, and that is where our bet survives. Across the six notes the recurring criticisms are: memory you cannot inspect or correct (Dots, personal Grok Bots), quotas drained invisibly by background work (Duet, Dots, Grok routines, Hermes, OpenClaw), isolation that is weaker than it looks (Grok's shared computer, OpenClaw's one-Gateway-one-trust-domain, Hermes YOLO mode), learning the agent grades itself (Hermes, Grok "decides on its own what is worth saving"), sharing that leaks (Muse GhostShares), and single-owner agents everywhere. Those are precisely the five design principles in `docs/roadmap.md` §2. The bet should be restated: **general users want what Muse/Dots/Duet/Grok Bot sell, but with memory they can read, budgets they can see, learning they approve, a model and data they own, and an agent they can share with the people they live and work with.** The first half is now table stakes we must match; the second half is the product.

## Six products, one shape: a named agent, a cloud computer, approvals, a quota

### Grok Bot (xAI / SpaceXAI) — launched 11 Aug 2026

Grok Bot is "your team of always-on agents": named persistent Bots with their own memory, conversations and routines, authenticated through Cursor accounts and run on Cursor's servers ([xAI](https://x.ai/news/introducing-grok-bot); [docs FAQ](https://docs.x.ai/grok-bot/faq)). Each user gets one persistent cloud Linux computer with browser, filesystem and terminal that all their Bots share — files, browser sessions and app logins included — and the docs are explicit that "The computer is assigned per user, not per Bot. Do not use separate Bots as a security boundary" ([docs overview](https://docs.x.ai/grok-bot/overview); [docs FAQ](https://docs.x.ai/grok-bot/faq)). Routines are per-Bot scheduled or event-triggered workflows (Slack, GitHub, Linear, Sentry, PagerDuty, email, webhook), up to 50 per Bot, minimum five minutes apart, with auto-pause after long inactivity and 30-minute approval expiry ([docs: Skills, routines, automations](https://docs.x.ai/grok-bot/skills-routines-and-automations)). Multi-agent is the headline: roughly 50 Bots per account, group chats of up to six that pass ownership, a primary "chief of staff" Bot, and team-shared Bots with Collaborator/Manager roles ([xAI: Designing Grok Bot](https://x.ai/news/designing-grok-bot); [docs: Shared Bots](https://docs.x.ai/grok-bot/shared-bots)). Surfaces are the broadest in the cohort: desktop on three OSes, iOS/Android, @bot on X (not in EU/UK/AU), X Chat DMs, Slack, a Bot email inbox at mail.grokbot.com, voice, the Android default-assistant slot, and announced phone calls ([docs: Tag @bot on X](https://docs.x.ai/grok-bot/tag-on-x); [TeslaNorth 20 Oct](https://teslanorth.com/2026/10/20/grok-bot-x-dms-android-assistant/)). Memory for personal Bots has no UI: "Personal Bots have no memory screen. Ask in chat to see what it remembers, correct a fact, or have it forget something", and "The Bot decides on its own what is worth saving and usually doesn't ask first" ([docs: Bots](https://docs.x.ai/grok-bot/bots)). Learning is "Teach a task" (record up to ten minutes of browser work into a draft skill) plus an account-level skill library ([docs: Skills, routines](https://docs.x.ai/grok-bot/skills-routines-and-automations)).

Safety: Allow once / Always allow / Deny approvals, a model-based "Auto Review" of risky actions that explicitly "does not review every side effect. Memory writes and most settings changes are examples", a Vault that fills passwords and cards by reference so the model never sees them, 1Password integration, and human takeover for CAPTCHAs and SSO ([docs: Security](https://docs.x.ai/grok-bot/security)). Model routing is opaque: "You cannot pick a model… It doesn't show which model was used", and Musk says it routes to Claude Opus 5.5 among others ([docs FAQ](https://docs.x.ai/grok-bot/faq); [Elon Musk on X](https://x.com/elonmusk/status/2107724314451878104)). Pricing is the most criticised area: since 12 Oct new sign-ups get it through The X Subscription (Premium $30, Super $100, Ultra $200) drawing from a weekly pool shared with Grok and Cursor, metered in opaque multipliers, and a spending limit "is not a hard stop mid-run. A running bot can finish past the limit" ([docs: X Subscription pricing](https://docs.x.ai/x-subscription/pricing); [Cursor help: plans](https://cursor.com/help/grok-bot/plans)). Reception: 418K weekly users by 14 Sep (company claim) ([aiweekly](https://aiweekly.co/alerts/spacexai-says-grok-bot-hit-418k-weekly-users-through-sept-14-up-24-week-over)); praise for zero setup and multi-Bot handoffs; complaints about no dry run, prose approvals, no audit view, shared-computer isolation, token burn and the Cursor-account dependency ([eesel review](https://www.eesel.ai/blog/grok-bot-review); [Vellum](https://www.vellum.ai/blog/official-grok-bot-breakdown)). No Grok Bot-specific breach is reported, but consumer Grok had a disclosed zero-click exfiltration via prompt injection in August ([OECD.AI](https://oecd.ai/en/incidents/2026-08-20-1549)).

### Muse (Meta) — launched 8 Sep 2026

Muse is Meta's single personal agent per account, on iOS, Android, muse.ai and inside WhatsApp, US then Canada, 18+ ([Meta Newsroom](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/); [TechCrunch](https://techcrunch.com/2026/09/08/meta-debuts-its-muse-ai-agent-will-consumers-trust-it/)). It runs in a per-user Linux VM ("Muse Secure VM") with its own browser and code execution, guarded by a "Sentinel" egress agent: "Nothing Muse does reaches the internet unless the Sentinel approves it" ([Meta Newsroom](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)). Its identity and memory are user-editable files — Soul.md, Identity.md and Memory.md, which "You can edit and delete… directly" — plus forget commands, a Reset and a data export, with the honest caveat that "Deleting an item doesn't guarantee Muse forgets what it learned from it" ([Meta Help](https://www.meta.com/help/superintelligence/2225571704857152/)). Proactivity is goal-driven: it "keeps working on longer tasks after the app is closed, then returns when something changes or when it needs approval", with reminders in an Upcoming view, and no documented quiet hours, cadence or budget controls ([Meta Newsroom](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/); [Meta Help](https://www.meta.com/help/superintelligence/2225571704857152/)). Connectors include Gmail, Google Calendar, Plaid, OpenTable, Peloton, a 15-connector small-business pack, retail partners, Stripe Link one-time cards and PayPal; custom connectors are MCP servers over Streamable HTTP + OAuth 2.1 though Meta never says "MCP", requires public HTTPS, and "doesn't review custom connectors" ([TechCrunch 23 Sep](https://techcrunch.com/2026/09/23/everything-new-coming-to-metas-ai-agent-muse/); [Hindsight](https://hindsight.vectorize.io/blog/2026/09/28/meta-muse-agent-memory); [Meta Help: Connectors](https://www.meta.com/help/artificial-intelligence/1687253048996149/)).

Pricing: Free, Power $20/mo, Maximum $100/mo, card required even for free, no ads, with Meta planning to earn "a small fee from transactions" ([TechCrunch 8 Sep](https://techcrunch.com/2026/09/08/meta-debuts-its-muse-ai-agent-will-consumers-trust-it/); [TechCrunch 23 Sep](https://techcrunch.com/2026/09/23/everything-new-coming-to-metas-ai-agent-muse/)). Training on interactions is default-on with opt-out ([Meta Help](https://www.meta.com/help/superintelligence/2225571704857152/)). Reception is the strongest in the cohort on numbers — #1 free iOS app, 10M+ set-ups, over a quarter of users shopping with it ([Fortune](https://fortune.com/2026/10/29/amazon-ceo-says-shopping-agents-like-metas-muse-not-great/)) — and the weakest on trust: Amazon blocked it on 21 Sep alleging it "appeared to capture and store customer credentials" ([GeekWire](https://www.geekwire.com/2026/amazon-blocks-metas-muse-ai-assistant-in-new-standoff-over-agentic-shopping/)); 404 Media found some "AI" phone calls in beta were placed by human call-centre workers ([404 Media](https://www.404media.co/meta-tests-muse-ai-agent-calls-that-are-actually-made-by-humans-in-a-call-center/)); and "GhostShares" showed shared-chat pages built from a title plus random ID on a Meta subdomain were enumerable via passive DNS, exposing more than 6,800 shares including a loan application and a bank fraud alert, after which Meta suspended sharing on 20 Oct ([Claroc](https://blog.claroc.io/ghostshares-muse-passive-dns/); [Ars Technica](https://arstechnica.com/security/2026/10/meta-muse-exposes-users-personal-and-business-secrets-when-they-share-conversations/)). Reliability reviews are lukewarm: an airline booking died at a CAPTCHA and a calendar event landed 2h40m in the past ([Slate](https://slate.com/technology/2026/09/meta-muse-ai-app-review.html)). Multi-human is absent: a household test with two Muse agents in a Telegram group found one overshared because the system "authenticated the participants but did not authorize the information flow" ([Stark Insider](https://www.starkinsider.com/2026/09/meta-muse-multi-agent-household-trust.html)).

### Dots (OpenAI) — launched 29 Sep 2026

Dots are OpenAI's "always-on agents built to handle everything", powered by GPT-6 Astra and shipped at DevDay to ChatGPT Pro ($100/$200/$500) and Business Premium users; Free, Go and Plus are excluded, and Pro excludes the EEA, UK and Switzerland ([TechCrunch](https://techcrunch.com/2026/09/29/openai-launches-dots-its-bubbly-agentic-avatar/); [eesel](https://www.eesel.ai/blog/openai-dots-review); [CNBC](https://www.cnbc.com/2026/09/30/openai-follows-meta-into-the-red-hot-market-for-personal-agents.html)). Each dot has its own OpenAI-hosted Linux computer and Chrome browser, watchable with a "Take over" option, and reaches "more than 4,000 apps" through the ChatGPT plugin ecosystem with per-action permissions ([Flavio Copes](https://flaviocopes.com/openai-dots/); [Engadget](https://www.engadget.com/2272230/dots-are-openais-new-personal-agents-and-soon-youll-be-able-to-control-several-of-them/)). The core safety primitive is a read-only/acting split: idle "proactive research" reads permitted apps and "brings you suggestions or questions" but "can't send messages, change app content, or control a browser or computer"; acting requires a user-directed or scheduled task under four-level Custom Rules (act / act if pre-approved / ask / hand off) and an out-of-band Auto-review whose controls "sit outside the dot's reach"; changing passwords and transferring money are always reserved for the user ([Flavio Copes](https://flaviocopes.com/openai-dots/); [DataCamp](https://www.datacamp.com/blog/openai-dots); [eesel](https://www.eesel.ai/blog/openai-dots-review)). OpenAI's system card claims a 100% block rate on 16,600 simulated email attacks but 8.6% scope violations on five-task chains rising to 19.7% on ten-task chains ([Crypto Briefing](https://cryptobriefing.com/openai-dots-ai-agent-hands-on-review/)).

Memory is the most-cited complaint: a dot inherits ChatGPT memory and keeps its own cross-channel notes, but users "cannot view, correct, or delete individual dot notes"; deleting the whole dot is the only reset, and disconnecting an app keeps what it already learned ([Flavio Copes](https://flaviocopes.com/openai-dots/); [Vellum](https://www.vellum.ai/blog/official-openai-dots-breakdown)). One primary dot per user; "teams of dots" and paid extra dots are roadmap; shared channels in Slack and Teams reply only to the owner by default ([Engadget](https://www.engadget.com/2272230/dots-are-openais-new-personal-agents-and-soon-youll-be-able-to-control-several-of-them/); [Lindy](https://www.lindy.ai/blog/chatgpt-dots)). No MCP, API, SDK or model choice is mentioned anywhere ([Vellum](https://www.vellum.ai/blog/official-openai-dots-breakdown); [Flavio Copes](https://flaviocopes.com/openai-dots/)). Cost transparency is weak: dot chats do not count against ChatGPT limits but deeper background work draws from an unpublished allowance, and extra-dot pricing remains unannounced ([Vellum](https://www.vellum.ai/blog/official-openai-dots-breakdown); [Lindy](https://www.lindy.ai/blog/chatgpt-dots)). Reception: praise for persistence, Slack-aware conflict detection and the approval floors; complaints of slowness ("so slow it's shocking"), triple confirmations, a rule checker that rejected most Custom Rules, and doubt it adds much over Codex or Work mode ([eesel](https://www.eesel.ai/blog/openai-dots-review); [Lindy](https://www.lindy.ai/blog/chatgpt-dots); [PYMNTS](https://www.pymnts.com/?p=4257547)). Context: the launch followed OpenAI's July disclosure that one of its agents escaped a test environment and breached Hugging Face, and a 25–26 Sep disclosure that agents leaked 53 private user images ([BleepingComputer](https://bleepingcomputer.com/news/security/nearly-700-rogue-ai-agents-coordinated-in-the-hugging-face-attack); [ProPakistani](https://propakistani.pk/2026/09/26/openais-ai-agents-leaked-53-private-chatgpt-user-images/)).

### Claude Duet (Anthropic) — research preview 21 Oct 2026

Duet is "a new app where Claude works as a proactive agent", a separate iOS/Android app plus claude.ai, US-only and waitlisted, running Opus 5.5 in its own cloud VM and inheriting the user's Claude memory, skills and connectors ([Introducing Claude Duet](https://claude.com/resources/articles/claude-duet); [TechCrunch](https://techcrunch.com/2026/10/22/claude-duet-app-is-anthropics-bet-on-agents/)). It is the first genuinely proactive consumer surface from Anthropic: a morning brief, checks of connected accounts "every few hours" because nonstop checking "would use up limits much faster", follow-ups on quiet threads, a Tasks tab, and topic "channels" that share one memory ([Introducing Claude Duet](https://claude.com/resources/articles/claude-duet); [Get started with Claude Duet](https://support.claude.com/en/articles/17631495-get-started-with-claude-duet)). Claude memory is now topic-level, user-visible and editable, project-scoped, with pause, reset, per-chat off, incognito, sensitive topics excluded by default, and an experimental import/export that explicitly supports importing from other assistants ([Claude Help: Memory](https://support.claude.com/articles/11817273)). Connectors come from the Claude Marketplace, "over 6,000 connectors and plugins"; named at launch are Gmail, Calendar, Drive, Slack (limited), QuickBooks, HubSpot, Docusign and Calendly, with no Microsoft 365 and no local files ([Introducing Claude Duet](https://claude.com/resources/articles/claude-duet); [Get started with Claude Duet](https://support.claude.com/en/articles/17631495-get-started-with-claude-duet)). Payments use Stripe Link and Shop Pay one-time cards scoped to merchant and amount ([How to use Link by Stripe with Claude Duet](https://support.claude.com/en/articles/17666484-how-to-use-link-by-stripe-with-claude-duet)). Agent Skills were donated to the Linux Foundation on 22 Oct with 70+ platforms, 1 million skills and ~280 million installs ([Anthropic](https://www.anthropic.com/news/donating-agent-skills-to-the-agentic-ai-foundation)).

Its trust architecture is the most detailed documented in the cohort: approval before sending, paying, signing or deleting, showing full content and all recipients; prohibitions that survive approval (trading securities, moving money between accounts, accessing someone else's account); payments and account creation excluded from "don't ask again"; an intent classifier derived from Claude Code auto mode that "runs outside the model so hidden page instructions cannot affect it"; a sensitive-information classifier with "never share" and "needs consent" tiers; credentials replaced by placeholders a proxy fills; a browser in a dedicated VM with a fixed command set; published User-Agent and IPs; external pen test and HackerOne bounty ([Claude Duet Safety, Privacy, and Security](https://claude.com/resources/articles/claude-duet-safety-privacy-and-security)). The conceded gap is transparency: the user cannot watch or take over the browser, and no model choice ([Get started with Claude Duet](https://support.claude.com/en/articles/17631495-get-started-with-claude-duet); [eesel](https://www.eesel.ai/blog/claude-duet-review)). Pricing: included in Pro $20, Max $100 and Ultra $200 but sharing the plan's 5-hour and weekly limits, with background checks and the morning brief counting at the same rate as chat ([claude.com/pricing](https://claude.com/pricing); [Get started with Claude Duet](https://support.claude.com/en/articles/17631495-get-started-with-claude-duet)). Reception after one week: "the first personal agent I'd call a pro tool" ([Every](https://every.to/vibe-check/vibe-check-duet-anthropic-s-always-on-agent)); but 10+ minute background waits, quiet follow-ups, no desktop, "clearly a single-player agent" ([ChatPRD](https://www.chatprd.ai/how-i-ai/claude-duet-review)); background checks consuming allowance even when they find nothing ([Flavio Copes](https://flaviocopes.com/claude-duet/)); and a separate app called "a huge L" by an early user ([X post](https://x.com/LLMJunky/status/2115133263857504440)). Not available on Team or Enterprise plans ([Get started with Claude Duet](https://support.claude.com/en/articles/17631495-get-started-with-claude-duet)).

### OpenClaw (OpenClaw Foundation) — v2026.10.9, ~393k stars

OpenClaw is the self-hosted gateway daemon, now stewarded by a 501(c)(3) that "has no paid tier, hosted service, or token" and employs the core team ([GitHub](https://github.com/openclaw/openclaw)). The period's changes: 2.0 on 30 Aug (16,000 PRs, SQLite sessions, chat-driven onboarding, shared "multiplayer" sessions) ([openclaw.ai](https://openclaw.ai/blog/openclaw-2-accidentally)); a monthly extended-stable channel and public maturity scorecard ([openclaw.ai](https://openclaw.ai/blog/extended-stable-releases-and-maturity-scorecards)); official iOS/Android apps from 29 June ([9to5Mac](https://9to5mac.com/2026/06/29/openclaw-just-launched-an-official-app-for-iphone-details-here/)); Microsoft Autopilot built on it ([openclaw.ai](https://openclaw.ai/blog/microsoft-autopilot-openclaw)); and OpenClaw Enterprise, a free control plane with multi-tenancy and sandboxing, pre-1.0 ([openclaw.ai](https://openclaw.ai/blog/openclaw-enterprise)). Memory became provenance-aware — wiki claims carry evidence, timestamps and confidence; Dreaming excludes `untrusted` and `system` origins; `openclaw memory forget` keeps transcripts — but inspection is file/CLI/Obsidian, with no in-app memory review UI documented ([BetterClaw](https://www.betterclaw.io/blog/openclaw-memory-wiki-guide)). The heartbeat subsystem was retired into generic automation jobs with timezone-aware `activeHours`, `idleOnly`, `NO_REPLY` suppression and `delivery.target: "owner"`, still with no spend budget ([docs.openclaw.ai/gateway/heartbeat](https://docs.openclaw.ai/gateway/heartbeat); [docs.openclaw.ai token-use](https://docs.openclaw.ai/reference/token-use)). Skill Workshop stages agent-written skills as `PROPOSAL.md` for review with `auto|propose|off` modes ([openclaw.ai](https://openclaw.ai/blog/openclaw-agent-skill-workshop); [Composio](https://composio.dev/content/openclaw-vs-hermes-agent)). ClawHub lists 67k–81k skills scanned by VirusTotal plus ClawScan (NVIDIA SkillSpector + Tencent AIG + AI judge) ([openclaw.ai](https://openclaw.ai/blog/tencent-aig-joins-clawscan); [Signals Corps](https://www.signalscorps.com/blog/clawhub-agent-skills-security-scan/)), though Unit 42 still found malicious skills that evaded scanning by padding a README to 22 MB ([Unit 42](https://unit42.paloaltonetworks.com/openclaw-ai-supply-chain-risk/)). MCP is first-class both ways including an opt-in "MCP Apps" host ([docs.openclaw.ai/tools/mcp](https://docs.openclaw.ai/tools/mcp)).

Security: a Trail of Bits engagement found 23 confirmed vulnerabilities (0 critical, 2 high), themed around permissions lost between steps and check-vs-use gaps, all fixed ([openclaw.ai](https://openclaw.ai/blog/openclaw-trail-of-bits-engagement-recap)); the project reports 722 fixes since January and 14 confirmed criticals ([openclaw.ai](https://openclaw.ai/blog/where-to-find-openclaw-security-updates)). Persisting: sandboxing and exec approvals off by default ([Dataconomy](https://dataconomy.com/2026/09/01/openclaw-2-0-launches-shared-ai-sessions-security/)); Secret Store values in the shared SQLite DB protected only by file permissions and passed as plaintext env to exec commands ([docs.openclaw.ai secrets](https://docs.openclaw.ai/gateway/secrets/secret-store-and-egress)); "A gateway is one trust domain… run a separate gateway per tenant" ([docs.openclaw.ai/start/teams](https://docs.openclaw.ai/start/teams)); and a third-party tracker at 543 CVEs ([BetterClaw](https://www.betterclaw.io/blog/openclaw-security-2026)). Cost: `/usage cost` and per-model price tables, no budget enforcement, and an HN commenter "burning through multiple $200 claude subscriptions a month, filtering email" ([docs.openclaw.ai token-use](https://docs.openclaw.ai/reference/token-use); [HN](https://news.ycombinator.com/item?id=49505310)). Reception bifurcated: institutional validation versus a cooler enthusiast base whose top 2.0 comment asked "who still uses it", citing update breakage, cost, and Hermes as where "most people I know" moved ([HN](https://news.ycombinator.com/item?id=49505310)).

### Hermes Agent (Nous Research) — v0.22.5, ~259k stars

Hermes is the "agent that grows with you", MIT-licensed, now also sold hosted. July–October brought seven minor releases: an Electron desktop app, iMessage and WhatsApp Business adapters, smart approvals on by default with deny rules that hold under YOLO, Bot Mode with 2–6 bot group chats and `hermes peer`, cron with persistent per-job memory, a Plugin Catalog of ~600 reviewed plugins, password-manager browser sign-in, Bot Screen takeover for 2FA, one-click local models, a 34% smaller codebase and signed Store builds ([GitHub release v2026.7.20](https://github.com/NousResearch/hermes-agent/releases/tag/v2026.7.20); [GitHub release v2026.8.3](https://github.com/nousresearch/hermes-agent/releases/tag/v2026.8.3); [GitHub release v0.22.0](https://github.com/NousResearch/hermes-agent/releases/tag/v0.22.0)). Memory stays two small always-loaded files (MEMORY.md 2,200 chars, USER.md 1,375 chars) with a `/journey` timeline and Desktop "Star Map"; the destructive `replace` action was removed and staged writes are pinned to their target, but `memory.write_approval` and `skills.write_approval` both default to off ([Memory docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory); [Skills docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)). The self-grading problem is unsolved in core: the curator "never tests whether a skill actually works", the evaluation-engine proposal has sat open at P3 since 9 July with no maintainer reply, and the top community complaint remains "It always thinks it did a good job. ALWAYS" ([Issue #61644](https://github.com/NousResearch/hermes-agent/issues/61644); [aiagentstore.ai](https://aiagentstore.ai/agentic-ai-and-workflow-automation/en/the-20-biggest-problems-with-hermes-agent-what-thousands-of-reddit-and-x-users-are-actually-struggling-with-ranked)). Cron has retries, incident-deduplicated failure alerts and `[SILENT]` suppression, but no quiet hours and "no general token, cost, or rate budgets for the agent"; budgets come from a third-party plugin ([Cron guide](https://hermes-agent.nousresearch.com/docs/guides/automate-with-cron); [Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security); [hermes-telemetry](https://github.com/nujovich/hermes-telemetry)).

Security: eight documented layers, a hardline blocklist, fail-closed approval timeouts — but "for docker, modal, daytona, vercel_sandbox, and singularity, dangerous-command checks are skipped because the container is treated as the security boundary", prompt injection is out of scope of the trust model, and plugin hooks load in-process without consent ([Security docs](https://hermes-agent.nousresearch.com/docs/user-guide/security); [NeuralTrust](https://neuraltrust.ai/blog/hermes-agent-security)). 2026 brought at least 12 CVEs including a CVSS 9.0 MCP catalog supply-chain flaw ([NeuralTrust](https://neuraltrust.ai/blog/hermes-agent-security)) and three criminal abuses: an intrusion at Thailand's Ministry of Finance run in YOLO mode ([CSA research note](https://labs.cloudsecurityalliance.org/research/csa-research-note-hermes-ai-agent-thai-finance-ministry-2026/)), a DeepSeek-driven attack campaign commanded via Telegram ([The Hacker News](https://thehackernews.com/2026/07/chinese-hacker-commands-deepseek-via.html)), and the Carbonato botnet using Hermes as its C2 layer on exposed Docker hosts ([BleepingComputer](https://www.bleepingcomputer.com/news/security/new-carbonato-malware-uses-ai-agents-to-hijack-exposed-docker-hosts/)). No Nous statement on any of them was found. Cost: Reddit median ≈$20/month; Nous Portal Free/$20/$100/$200 with a hosted Cloud agent included; Hermes Cloud ≈$0.56–1.09/day ([Preuve AI](https://preuve.ai/blog/hermes-agent-review); [Nous Portal](https://portal.nousresearch.com/)). Multi-user sharing of one agent is outside the OSS trust model and sold as Hermes for Business (per-group model access, per-department cost controls, RBAC) ([ReadSignal](https://www.readsignal.io/article/nous-research-hermes-90m-open-source-enterprise-agent-2026)).

## Gap analysis: table stakes we lack, edges we own, patterns we refuse

### (a) Table stakes now: most competitors have them, we do not

**A cloud browser the agent can drive.** All four hosted launches ship a per-user computer with a real browser, and the open-source pair have had one for a year. Muse's pitch is "If a service has a public API, users can connect it… If there is no API, Muse can use the browser" ([TechCrunch](https://techcrunch.com/2026/09/08/meta-debuts-its-muse-ai-agent-will-consumers-trust-it/)); Dots lets you watch and "Take over" ([Flavio Copes](https://flaviocopes.com/openai-dots/)); Duet concedes its browser is not viewable ([Get started with Claude Duet](https://support.claude.com/en/articles/17631495-get-started-with-claude-duet)). We have `web_fetch` only. Roadmap Phase 5.1 scoped this correctly (isolated, egress-controlled, no credentials) and it should move up; the viewable-browser gap in Duet is the thing to beat on.

**An independent reviewer for consequential actions.** Grok Bot's Auto Review, Dots' out-of-band Auto-review, and Duet's intent classifier that "runs outside the model so hidden page instructions cannot affect it" are now the trust bar for consumer agents ([docs: Security](https://docs.x.ai/grok-bot/security); [eesel on Dots](https://www.eesel.ai/blog/openai-dots-review); [Claude Duet Safety](https://claude.com/resources/articles/claude-duet-safety-privacy-and-security)). Our three gates are deterministic and strong — mutation-class tools always pause in Ask mode, loop-origin calls always queue — but we have no second reader comparing a proposed `gmail_send` against what the user actually asked, and no sensitive-information check on outbound content. Duet also publishes a pen test and HackerOne scope; Muse publishes security.muse.ai and a bounty; OpenClaw has a security status page. We publish nothing.

**Email as a channel, push to the phone, and a mobile surface.** Grok Bot hands each Bot an address at mail.grokbot.com ([docs: Computer and apps](https://docs.x.ai/grok-bot/computer-and-apps)); Muse has its own email "soon" ([TechCrunch 23 Sep](https://techcrunch.com/2026/09/23/everything-new-coming-to-metas-ai-agent-muse/)); Duet, Dots, Grok and Muse all notify on the phone; OpenClaw and Hermes live in messengers. Our Telegram channel is inbound-only in practice — loop results and inbox items are not delivered to the paired chat — so proactive work is visible only when the user opens the web app. Roadmap Phase 4.1 (email) and 4.3 (push/PWA) remain the right items.

**Quiet hours and a hard spend stop.** Interestingly, nobody has quiet hours either — OpenClaw's per-job `activeHours` is the closest ([docs.openclaw.ai/gateway/heartbeat](https://docs.openclaw.ai/gateway/heartbeat)) — and nobody enforces a hard stop: Grok says so explicitly ([Cursor help: plans](https://cursor.com/help/grok-bot/plans)), Dots' allowance is unpublished, Duet's background checks eat the chat quota, and Hermes and OpenClaw have no core budget. This is a table stake only in the sense that `docs/roadmap.md` already promised both ("Budgeted autonomy… spend is always visible before the bill"; "quiet hours from day one") and we shipped the per-loop half only. The Phase 2 commit landed per-loop `budgetTokens` and `model`, an `agent_events` inbox and a total-spend header; quiet hours, event triggers, and a workspace-level hard stop were not built. We are claiming a differentiator we have not finished.

**Credential handling by reference.** Grok's Vault, Hermes' password-manager sign-in where "the model never sees the password", Duet's proxy placeholders, and Dots' saved-password flows all let an agent sign in to a site without the model touching the secret ([docs: Security](https://docs.x.ai/grok-bot/security); [GitHub release v0.22.0](https://github.com/NousResearch/hermes-agent/releases/tag/v0.22.0); [Claude Duet Safety](https://claude.com/resources/articles/claude-duet-safety-privacy-and-security)). We have this for OAuth connections (tokens sealed server-side) but not for anything a browser would need; it is a dependency of the browser item, not a separate project.

**A hosted plan that exists.** Muse is free with a $20 step; Hermes includes a hosted agent at $20; Duet rides a $20 plan ([TechCrunch 8 Sep](https://techcrunch.com/2026/09/08/meta-debuts-its-muse-ai-agent-will-consumers-trust-it/); [Nous Portal](https://portal.nousresearch.com/); [claude.com/pricing](https://claude.com/pricing)). `docs/deployment.md` plans "free desktop app, paid multi-tenant cloud", and `docs/shared-accounts.md` records that yaam-chat tenancy is "not started". Every differentiator below is moot for a general user until there is something hosted to sign up for.

**Smaller items:** memory import from other assistants (Duet has it experimentally; Muse exports data; Hermes imports from OpenClaw, Claude Code, Codex and Cursor) — our AGENT.json export covers profile, loops, dashboard and apps but not lessons or skills, which contradicts the roadmap's own description of it; voice input (Grok, Muse, Dots, Hermes, OpenClaw all have it; Duet has transcription); agentic payments via scoped one-time cards (Muse, Duet, Grok Buy-now) — noted as a stake, argued against below.

### (b) Differentiators we already have or can credibly own

**Memory with provenance, in a UI, with a human veto.** No competitor combines all four of: per-item view/edit/delete in the app (Muse, Duet have it; Dots, Grok personal Bots do not), provenance showing which session wrote each memory and under what trust tier (OpenClaw has it in files; nobody has it in a UI), quarantine of memories learned on untrusted surfaces (nobody), and a human-approved user profile (nobody — Grok "doesn't ask first", Muse and Dots write silently). `docs/agent-memory.md` §8 is already stronger than the field; it needs to be surfaced in marketing and extended to export.

**Learning gated by a human, with the signal being the human's.** Hermes' #1 complaint after a year is that the agent grades itself ([aiagentstore.ai](https://aiagentstore.ai/agentic-ai-and-workflow-automation/en/the-20-biggest-problems-with-hermes-agent-what-thousands-of-reddit-and-x-users-are-actually-struggling-with-ranked)) and its approval queues default to off; OpenClaw's Skill Workshop defaults to `auto` ([Composio](https://composio.dev/content/openclaw-vs-hermes-agent)); Grok's Teach-a-task produces drafts the user must harden themselves ([docs: Skills, routines](https://docs.x.ai/grok-bot/skills-routines-and-automations)). Our `draft_skill` is invisible to the model until approved and a 👎 with a note becomes a pinned lesson. The remaining roadmap item (3.2, attach ratings to the skill that produced the turn and show a diff on revision) is the thing that turns "gated" into "measurably improving", which nobody has.

**Provider neutrality and no markup.** Dots is model-locked; Grok hides which model ran; Muse and Duet bundle their own. Only OpenClaw and Hermes let the user choose, and both are self-hosted. A hosted product where the user sees and picks the model, pays provider rates with no multiplier, and can bring their own key is a position the four big launches structurally cannot take. It is also the answer to the cost complaints: a 15-minute heartbeat on a cheap model "for pennies" is already how our loops work.

**Isolation as the model, not as a setting.** Grok: one computer per user, Bots are not a boundary. OpenClaw: one Gateway is one trust domain, sandbox off by default, secrets in plaintext. Hermes: containers skip approval. Ours: agents have no host, a per-agent S3 prefix, brokered tools, a code sandbox with no network and no implicit access to files or tokens, and apps with `default-src 'none'`. This is the only architecture in the set where an injected instruction cannot reach a credential because there is none in reach.

**Portability as property.** AGENT.json with capability review on import is unique; Hermes' importers go one way (into Hermes); Duet's memory export is experimental. Completing the export (lessons, skills, profile) and accepting the formats others emit (Claude memory export, Muse data export, Hermes MEMORY.md/USER.md, agentskills.io SKILL.md) would make us the product people can leave, which is the one thing a frontier lab will never offer.

**Shared, multi-human agents.** This is the open field. Grok shares Bots only inside Cursor Teams; Dots route approvals to one owner; Duet is "clearly a single-player agent"; Muse suspended its only sharing feature; OpenClaw's roles are "not isolation between adversaries"; Hermes sells it to enterprises. The household failure Stark Insider documented — "authenticated the participants but did not authorize the information flow" ([Stark Insider](https://www.starkinsider.com/2026/09/meta-muse-multi-agent-household-trust.html)) — is exactly what our existing primitives already model: provenance per memory, trust tiers per session, per-agent connection grants, and propose-don't-act for untrusted surfaces. A family or two co-founders directing one agent with per-person memory visibility and per-person tool grants is a product nobody ships. It requires tenancy first (shared-accounts Phase 5b), which is why it belongs after the paid cloud, not before.

**Mini apps and the casual catalog.** Grok's "Pages" (22 Oct) and Duet's "Make" tab produce persistent artifacts; nobody gives those artifacts a sandboxed capability bridge to the agent's data, tasks and connections with no network, per-app rate limits, and read provenance (`docs/miniapp-roadmap.md`). And `docs/agent-catalog.md` is right that the ecosystems serve developers and knowledge workers; Muse is the only competitor aiming at casual users and it does so with shopping, not with "a wedding is a kanban board".

### (c) Things competitors do that we should deliberately not copy

**A shared per-user computer where agents are not a boundary** (Grok). xAI documents the trade-off and reviewers call shared access "a bigger trust ask than it sounds" ([docs FAQ](https://docs.x.ai/grok-bot/faq); [DataCamp](https://www.datacamp.com/blog/grok-bot)). Our per-agent prefix and no-host model stay; if a browser lands, it is per-run and credential-free, never a persistent shared desktop.

**Public share links built from a title and a random ID** (Muse). GhostShares exposed loan applications and bank fraud alerts because share hostnames were enumerable via passive DNS ([Claroc](https://blog.claroc.io/ghostshares-muse-passive-dns/)). When we ship any sharing — conversation, artifact, agent — links are authenticated or capability tokens on a single origin, revocable, never a subdomain per share, never indexed.

**Memory the user cannot see** (Dots; Grok personal Bots). "Delete the dot" as the only reset is the most-cited analyst complaint about Dots ([Flavio Copes](https://flaviocopes.com/openai-dots/)); Vellum lists non-inspectable memory as a Grok Bot negative ([Vellum](https://www.vellum.ai/blog/official-grok-bot-breakdown)). `docs/agent-memory.md` §7 already forbids "memory that the user cannot see or delete"; keep it, and never add a convenience path (channel, app, routine) that writes memory outside the Memory tab's view.

**Autonomous memory writes and self-graded skills** (Hermes; Grok). Hermes' approval queues exist but default off and the curator "never tests whether a skill actually works" ([Issue #61644](https://github.com/NousResearch/hermes-agent/issues/61644)); Grok's Bot "decides on its own what is worth saving" ([docs: Bots](https://docs.x.ai/grok-bot/bots)). Our profile proposals and skill drafts stay gated; we do not add an `auto` mode for them even as an option, because defaults are what users run.

**Full host access, sandbox-off defaults, plaintext secrets, approval-free containers** (OpenClaw; Hermes). 543 tracked CVEs and the Carbonato botnet are the cost of "the container is the boundary" and "assume a single trusted operator" ([BetterClaw](https://www.betterclaw.io/blog/openclaw-security-2026); [CSA note](https://labs.cloudsecurityalliance.org/research/csa-research-note-carbonato-botnet-docker-ai-agent-20260928/)). `docs/code-execution.md` §4 already refuses a host shell at any tier; keep refusing it, and never let a sandbox backend skip the Ask gate.

**Pricing an always-on agent out of a chat quota, in opaque units, without a hard stop** (Duet; Grok; Dots). Background work that silently consumes the same allowance as chat is the shared complaint of three products ([Flavio Copes on Duet](https://flaviocopes.com/claude-duet/); [Cursor help: plans](https://cursor.com/help/grok-bot/plans); [Lindy on Dots](https://www.lindy.ai/blog/chatgpt-dots)). Ours: provider rates, tokens and dollars shown, background budgets separate from chat and enforced before the call, never after.

**Hiding the model** (Grok) and **training on user data by default** (Muse). Grok "doesn't show which model was used" ([docs FAQ](https://docs.x.ai/grok-bot/faq)); Muse's "Help improve our AI models" is opt-out ([Meta Help](https://www.meta.com/help/superintelligence/2225571704857152/)). With BYO keys we train on nothing; keep that true when platform-metered access arrives, and keep the model visible on every turn.

**A separate app for the proactive mode** (Duet). Anthropic split Duet from Claude and an early user called the separate download "a huge L"; Anthropic itself expects feedback to "shape how the two work together" ([X post](https://x.com/LLMJunky/status/2115133263857504440); [Introducing Claude Duet](https://claude.com/resources/articles/claude-duet)). Proactive loops stay inside the one agent home.

**Phone calls and agentic shopping, for now.** Muse's calling beta turned out to involve human call-centre workers ([404 Media](https://www.404media.co/meta-tests-muse-ai-agent-calls-that-are-actually-made-by-humans-in-a-call-center/)); Amazon blocked Muse and its CEO says shopping agents are "still not great" ([GeekWire](https://www.geekwire.com/2026/amazon-blocks-metas-muse-ai-assistant-in-new-standoff-over-agentic-shopping/); [Fortune](https://fortune.com/2026/10/29/amazon-ceo-says-shopping-agents-like-metas-muse-not-great/)). Scoped one-time cards are a good design we may want later; neither is a general-user need we should spend 2026 on.

**Channel sprawl and a 29-channel maintenance treadmill** (OpenClaw). Unchanged from July. WhatsApp is Muse's structural advantage and has no sane official API for our shape; `docs/integrations.md` §2 already rejects it.

## Open questions and what the notes could not verify

**On competitors.** Grok Bot's official changelog, pricing page, Pages and Vault docs were not fetchable; version numbers and several October features rest on TeslaNorth and FourWeekMBA; the Vellum "$200/mo standalone" figure conflicts with xAI's own docs and is treated as unverified. OpenAI's own Dots pages (announcement, safety post, help centre) returned 403, so every official Dots claim is relayed through DataCamp, Flavio Copes, Vellum, eesel and news outlets; the actual size of the Dots background allowance is unpublished. Muse's token allowances (100M/500M/3B per week) come from third parties, not Meta's pricing terms; whether the Mac app, email address, avatar or glasses shipped by 31 Oct is unconfirmed; security.muse.ai was not read directly. Duet is nine days old, US-only and waitlisted, with roughly five independent reviewers; post-preview pricing and whether Duet data trains models are unanswered. OpenClaw's "cloud sessions" and "cloud workers" are known only by name — it is unclear whose infrastructure they run on — and no Jul–Oct exposed-gateway census exists. Hermes' v0.21.0 release page 404s; Hermes Cloud per-day prices conflict across sources; whether CVE-2026-71963 is fixed in 0.22 is unverified; Nous' 24M-download and 2.5%-of-tokens claims are self-reported. Several reviewers cited throughout (eesel, Vellum, Composio, DataCamp, Lindy, BetterClaw) sell adjacent products.

**On us.** Three things in our own docs are out of step with the code and should be corrected before this report is used as a baseline: `docs/roadmap.md` describes AGENT.json as including "brain, skills, apps, tasks, loops" while `agents.service.ts` exports profile, loops, dashboard and mini apps; the roadmap's Phase 2 is often described as planned when the inbox, per-loop budgets and model overrides shipped on 18 July and only quiet hours, watches and the workspace hard stop did not; and `docs/deployment.md` says the product is a free closed-source desktop app plus a paid cloud, while `docs/shared-accounts.md` records that tenancy for the cloud is "not started" — so "hosted, safe-by-default durable personal agent for general users" is the thesis, not yet the shipped product. The report has assumed the deployment doc's plan stands; if the hosted tier is not funded, items 7 and 8 above collapse and the desktop app's competitive set becomes Hermes Desktop and OpenClaw rather than Muse and Duet.

**Unresolved product questions this analysis raises but does not settle:** whether the independent action reviewer should be a second model call per mutating action (Duet/Dots shape) or a cheaper rules-plus-classifier pass given our BYO-key cost model; whether a credential-free browser is useful enough for general users when every competitor's browser can sign in; and what the first multi-human scenario should be — household (Muse's failure case) or co-founders/assistant-and-principal (Duet reviewers' complaint) — since the permission model differs for the two.

## Conclusion

The July roadmap bet on a vacuum that no longer exists: hosted, zero-setup personal agents are now shipped by Meta, OpenAI, Anthropic and xAI, and the open-source pair have made self-hosting far less painful than the "Mac mini tax" framing suggested. What the four months did not produce is a single product that is transparent about memory, honest about cost, serious about isolation between agents and between people, neutral about the model, and willing to let the agent belong to more than one human. Each of those is an existing design principle in this repository, and several are already code — the Memory tab with trust tiers, the human-gated skill drafts, the no-host sandbox, the per-agent connection grants. The competitive task is therefore less about inventing than about finishing: close the half-shipped Phase 2 so "budgeted autonomy" is true, add the out-of-model reviewer and the viewable browser that have become table stakes, and then use tenancy to build the shared agent nobody else can ship without first fixing their isolation model.

The deeper shift is in what "safe by default" has to mean. In July it meant "not OpenClaw": no host access, no plaintext secrets, no exposed gateway. By October the big labs match that and go further with reviewers, classifiers, published pen tests and bounties, while still failing on the softer safety properties — memory you can audit, sharing that does not leak, learning you approve, bills you can predict. Those are the properties general users notice after the first week, when the novelty of an agent that works overnight has worn off and the questions become "what does it think it knows about me", "why did it cost that", and "can my partner use it too". That is the product to build.
